# Manager review: 2026-10-31

**No PDF brief in the repo.** I searched the whole tree (excluding node_modules) and found no `*.pdf`. Sources used: standing instructions, README.md, WORKLOG.md (Rounds 4 to 6), the agent definitions, and the agent reports passed in by the main session.

## Verdict

**Needs fixes first.** The performance-optimizer and visual-polish changes are clean: they stay in lane, don't conflict, and all four test suites pass. But the change set adds one WCAG AA contrast failure in strong-contrast mode and one target under 44px in big-button mode. Both are in the new voice CSS. They're two small CSS edits for visual-polish. Applying my rule that accessibility wins, these should land before the commit. Commits should also wait until the other session (Rounds 5 and 6) finishes in `pawthfinder.js`, as WORKLOG says.

## Conflicts

No real conflicts. Checked:

- **pawthfinder.js, perf vs the user's voice work:** they touch different functions. Perf changed `schedule()`, the observer's `schedule(16)`, `renderHazards()` (~L1062-1080) and `repair()` (~L847-876). Voice replaced `handleCommand`/`chooseIt`/`tickIt`, added `voice`/`DISPATCH`/`promptAccount`, and added one line to `tick()` (`if (voice.numbers) showNumbers(true)`). They interact only there: with numbers shown, `showNumbers` now runs 16 ms after every portal change instead of 120 ms. That's acceptable, and only applies while numbers are on screen.
- **Removed presets:** the `.pf-presets` / `.pf-preset` rules, the narrow-screen `.pf-presets{display:none}` and the HC `.pf-preset[aria-pressed]` selector are all gone from pawthfinder.css. No CSS refers to preset markup any more. `PRESETS`, `applyPreset` and `.pf-preset-desc` (L399, L1879) still exist on purpose for `?mode=` links.
- **CSS against JS markup:** I compared every `.pf-*` class selector in the three CSS files with the classes that pawthfinder.js, needs.js, dog.js and account.js produce. Every selector matches something. `pf-done` and `pf-warn` are built dynamically (`pf-${st}`, notice type). voice.js produces no markup. The new voice classes (`pf-saycard`, `pf-nums`, `pf-num`, `pf-dictating`, `.pf-heard[data-state]`) all have rules.
- **Badge:** JS already set `el.badge.hidden` (L1062, unchanged since HEAD). The new `.pf-badge[hidden]{display:none}` makes it work. Complementary, not a conflict. (My scratch check saw `hidden:false, text "1"` only because a warning really was open.)
- **voice.js preload:** `portal/index.html` preloads exactly the 6 files the loader injects at the bottom, in the same order, including `voice.js`. `?pf=0` skips both. perf reports 9 requests and 67.3 KB for the portal with Pawthfinder, so nothing downloads twice.
- **Bubble width coupling (heads-up, not a clash):** pawthfinder.css L201 caps the big-mode bubble at 250px *because* `positionDog()` L824 hardcodes `- 250`. If a JS agent fixes F6 by measuring `el.bubble.offsetWidth`, the CSS cap can stay or go back to 290px. Only visual-polish should make that call, and only after the JS lands.

Duplicate rules. They don't contradict each other but could be merged (visual-polish, low priority):
- account/account.css L12 and L13: two `.acct h2` rules back to back.
- site.css L46-47: `.nav ul a.nav-cta` twice. L54/L57 and L55/L58: `.btn.primary` and `.btn.primary:hover` twice.
- pawthfinder.css: `.pf-btn` twice (transition split out), `.pf-btn.pf-primary` twice (L80-81), `.pf-tabs [role=tab]` twice, and `.pf-bubble` max-width in its own rule at L202.
- account/account.css L49: `.big-toggle:hover { border-color: #c9bea9;` has its closing brace on the next line. It's valid, just untidy.

Checked and fine:
- **Contrast:** the new palette uses pass AA. Unselected tabs #4a5568 on the tray #f3ead9 are about 6.3:1. The eyebrow #0b5563 on #e3f1f3 is about 7.3:1. The command box border #8a7f6c on white is about 3.9:1 (3:1 needed). The done-step badge, white on #1f7a4d, is about 5.3:1. The dictating mic, white on #8a4b00, is about 6.8:1. Hovering the primary button (white on #0e6e7f) gives about 5.9:1.
- **Strong contrast:** new HC overrides exist for the tab tray, login card, review cards, stepper badge, `.top .btn` and number badges. `--pf-warn-bg` becomes #000 in HC, so the new amber highlight on `.pf-steps li.pf-now` keeps white text on black.
- **Reduced motion:** site.css now also disables transitions under `prefers-reduced-motion`. pawthfinder.css gained a `prefers-reduced-motion` block beside `html.pf-rm`. The new `pf-fade`/`pf-rise` animations are on `.pf-onboard`, which is inside `.pf-ui`, so both paths cover them.
- **Targets:** nav links 44px, `.btn` 48px, `.pf-icon` 40px by default (44px in big mode), chips 34px by default and 44px in big mode (measured), the command box 44px, and the tips summary 44px.
- **Zoom/reflow:** the landing page at 342px has `scrollWidth 342 = innerWidth`, so F15 is fixed. At 683px with big text, the bubble's right edge is 683 of 683, so it's inside the viewport at that width.
- **Screen readers:** tick pseudo-elements use `content: "✓" / ""`, so F12 is fixed for tiles, steps and the stepper.
- Nothing new downloads: no web fonts (font stacks are system plus optional local OpenDyslexic). Fetch's password and consent rules weren't touched. No build step was added.

- **Tail wag** (pawthfinder.css L174/L217, site.css L75/L78): already uses `transform: rotate`, but on an SVG `<g>` it still repaints. Promote it with `will-change: transform` on `.pf-tail`, or wag a wrapping HTML element, and keep both reduced-motion paths.
